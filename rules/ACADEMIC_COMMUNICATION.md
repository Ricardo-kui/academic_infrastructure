# ACADEMIC_COMMUNICATION.md — 学术沟通与写作风格指南

## 总体原则

务实、理性、克制。用思考深度体现专业，不堆砌宏大词藻，不用文学性比喻。
学术写作的核心目标是**说服读者接受一个理论判断**，而非展示词汇量。

---

## 一、中文学术写作规范

### 1.1 句子层面

**避免"很 + 形容词 + 冒号"的AI句式。**
「实验设计很直接：」「结果很清晰：」「原因很简单：」都是典型的AI生成句式。问题在于它用一个形容词跳过了论证责任，而人类写作者会让事实自己说话，或者用更精确的动词和名词来承接。

改法示例：
- ❌「实验设计很直接：他们只对比了SFT和RL两组。」
- ✅「他们只对比了SFT和RL两组，实验设计上做了极简处理。」
- ❌「结果很清晰：RL模型正向迁移3.5-11%。」
- ✅「RL模型在OOD上正向迁移3.5-11%。」

**避免把动词或修饰语压缩成单字收尾。**
典型如「域名往上追」「年份近」「机构真」「格式齐」：读起来像电报或笔记，不像自然写作。改成「顺着域名追踪」「年份较近」「机构真实」「格式齐整」。核心判断标准：去掉上下文后这个单字还能不能独立成义。

**避免笼统的方向描述。**
「往反方向走」「往坏的方向发展」「正在往另一个方向演进」都属于这类。直接写具体变化。

**句子尽量平直、自然。**
能拆成两句的拆成两句，能用冒号或分句表达的不用破折号做情绪性停顿。不用引号包裹概念词（除非绝对有歧义需要标记）。

### 1.2 修辞与比喻

**对系统、抽象概念和分析判断，少用口语化比喻。**
不要使用「长出来/长出了」「很硬」「很锋利」「收口」「很稳」「更稳」「击穿」「拆解」「闭眼编」这类表达。直接写清楚它是如何演化的、问题在哪里、差异体现在哪个维度。

**禁用的口语化/战争比喻词**：
「长出来/长出了」「很硬」「很锋利」「收口」「很稳」「更稳」「击穿」「拆解」「闭眼编」

**不要用「结构性」这个词。**
「结构性原因」「结构性矛盾」——直接写具体机制、约束来源或冲突位置，让读者知道到底是哪一层出了问题。

**少用「崩」「撑不住」「撑不起」概括系统或论证状态。**
「崩」是笼统判断，改成可核对的说法：异常终止、请求失败、会话漂移、输出质量下降、前提不成立。

### 1.3 元评论

**不要用元评论代替论证。**
元评论是标注自己正在做什么（"这篇文章回答什么""一个更一般的判断""回到X场景"），而不是推进论证本身。

具体症状：
- 标题或段首用元评论代替直接进入内容
- 用「这个框架」「这种说法」指代前文后做评价，而不是直接给出自己的判断
- 「不是X而是Y」句式在全文里反复出现作为论证框架

元评论占用的篇幅应该接近零。如果有必要做路标，用一句话带过，不要独占一段。

### 1.4 译文体

**不要写成英文表达方式的中文翻译。**
写完读一遍：若语序、隐喻和动词搭配像刚从英文逐句翻过来的，就按原意改成中文里自然的主谓结构和常用搭配。

典型硬译：
- 把 stand on 译成「站在某一层」→ 改为「属于哪一层」
- 把 serves 译成「服务的是」→ 改为「针对的是」
- 把 the evidence for X is clearer 译成「X的证据更直接」→ 改为「换到X上看更清楚」

### 1.5 承接词与节奏

中文句子之间依赖承接词维持节奏。这类承接词在语义上接近于零，但在阅读节奏上不可省略。AI写中文时容易因为觉得它们「没信息量」而全部省略，结果每句都像独立砸下来的砖头。

常用的承接词有几类：

- **起句承接**：这样做、这样一来、这里、这套东西、这件事、这套机制背后
- **轻转折**：不过、话说回来、至于、反过来看、换句话说
- **话题切换**：再往上看一层、回到开头那个矛盾、说到底、真正想说的是
- **对照标记**：代价是、好处是、麻烦在于、关键是、不一样的地方在于
- **语气词**：呢、吧、嘛

判断标准：把一段写完之后出声念一遍（不是心读），如果节奏像在念条目清单、没有呼吸感，大概率是承接词被省掉了。

注意分寸。承接词太密会显得啰嗦。默认做到「每段开头一个轻承接」，段中间已经顺的地方不再加。

### 1.6 链接文字要承载信息

不要用「前作」「这里」「之前讨论过的」这种抽象指代词做link text。Link text应该承载具体信息：文章名、功能名、或具体名词短语。

### 1.7 整体层面

- 不用华丽辞藻，不用「惊喜」这类营销词汇
- 不用「值得认真对待/值得深思/值得关注」这类居高临下的推荐语
- 直接写出它为什么重要、影响了什么判断
- 不说废话，不说客套话，直奔主题
- 用数据和逻辑说话，不靠形容词
- 不滥用bullet points，尽量用自然语言段落表达

## 二、英文学术写作规范

### 2.1 句子层面

**避免 inflated symbolism。**
不要把简单的实证发现包装成"paradigm shift""fundamentally transforms our understanding"。UTD期刊的读者是领域内专家，过度包装会削弱可信度。

**避免 superficial -ing analyses。**
"By examining..." "Through analyzing..." "In exploring..." 这种-ing开头如果没有实质性动作，只是填充。直接说"We find that..."

**避免 vague attributions。**
"Previous research has shown..." "It is widely accepted that..." —— 具体引用谁、在哪篇、什么发现。UTD期刊要求精确的文献对话。

**避免 passive voice overuse。**
被动语态在methods部分合理，但在introduction和discussion中过度使用会削弱作者的立场和判断。"We argue that" 强于 "It is argued that"。

**避免 negative parallelisms。**
"Not only does X affect Y, but it also influences Z" —— 这种结构如果X→Y和X→Z的理论逻辑不同，强行并列会显得牵强。

### 2.2 段落功能

**每个段落必须有且仅有一个功能。**
- Claim段落：提出一个论断
- Evidence段落：提供实证支撑
- Transition段落：承上启下
- 禁止一个段落里既claim又evidence又transition

**段首句必须承载段落核心信息。**
读者应该只读段首句就能把握全文结构。不要把关键信息藏到段落中部或尾部。

### 2.3 期刊特定语调

**AMJ / SMJ（理论贡献导向）**：
- 理论叙事优先，实证是支撑理论的工具
- 允许 bold claims，但必须有清晰的机制解释
- Introduction的前3句必须建立理论张力（tension）
- Discussion必须回到opening promises，不能只是result restatement

**MSOM / OS（分析方法导向）**：
- 识别策略的可信度必须前置讨论
- Mechanism clarity > story appeal
- Methods段落必须自解释（self-contained）
- Robustness检验必须系统、完整，不能是事后补充

**ASQ（过程理论/质性导向）**：
- 过程逻辑的时序性（temporal sequencing）必须清晰
- 因果机制的微观基础（micro-foundations）必须交代
- 叙事要有"呼吸感"：不是事件罗列，而是机制演化

### 2.4 翻译腔检查清单

写完英文后自检：
- [ ] 是否有中文思维的隐形结构（如"一方面...另一方面..."直译为"on one hand...on the other hand..."）
- [ ] 是否用了太多"In this study, we..."开头（variety: "We", "Our analysis", "The evidence suggests"）
- [ ] 是否有"very", "quite", "rather"等弱化词（UTD写作要求精确，弱化词 = 不自信）
- [ ] 是否有"etc.", "and so on", "and the like"（不专业，要么列全，要么用"among others"）
- [ ] 数字和单位之间是否有空格（"3.5%" ✓，"3.5 %" ✗）

## 三、引用格式规范

### 3.1 中文写作中的引用
- 使用 `[@citekey]` 格式，如 `[@AlShammariEtAl2025]`
- 关键证据后标注来源页：`（见 obs-lit-nca-alhadi-2023 的 "核心发现" 节）`
- 若文献无citekey，使用 `note_id` 指向笔记

### 3.2 英文写作中的引用
- 内文引用：Author (Year) 或 (Author, Year)
- 多作者：首次出现全列，后续et al.
- 页码引用：直接引用必须带页码 (Author, Year, p. 123)
- 避免"堆砌引用"：一个括号里塞5-6个引用是lazy writing，说明没有真正组织文献对话

## 四、禁止清单（AI写作红线）

| 禁止表达 | 替代方式 |
|---------|---------|
| "值得注意的是" | 直接写值得注意的内容 |
| "不难发现" | 直接呈现发现 |
| "本文旨在" | 直接说研究问题 |
| "本研究的意义在于" | 直接说贡献 |
| "首次发现" | 精确限定范围和边界条件 |
| "填补了空白" | 具体说明填补了哪一层理论空白 |
| "具有重要启示" | 具体说明对谁、在什么情境下的启示 |
| "未来研究可以..." | 把真正的limitation放在当前研究的边界讨论中 |

## 五、人机协作写作流程

1. **用户提出写作需求** → AI先读Context Packet和章节-证据映射
2. **AI输出初稿** → 遵循上述所有规范，标记不确定处为`[TODO: 用户确认]`
3. **用户审阅** → 关注理论逻辑和学术判断，不纠结措辞
4. **AI迭代** → 根据反馈修改，每次迭代只改1-2个核心问题
5. **最终QC** → 调用 `pollock-qc` 或对应 `*-review` skill 做投稿前检查

**核心原则：AI负责结构和表达的"机械正确"，用户负责理论判断和学术立场的"实质正确"。**
