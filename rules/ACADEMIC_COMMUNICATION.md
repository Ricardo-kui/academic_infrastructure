# ACADEMIC_COMMUNICATION.md — 学术沟通与默认表达风格

## 职责边界

本文件只定义中文表达的默认风格底线。英文写作规范和引用管理由对应 skill 负责（`write-*`、`humanizer`、`citation-management`）。

## 中文表达红线

避免用"很 + 形容词 + 冒号"引出解释，例如"结果很清晰：""原因很简单："。直接写事实或机制，让判断由内容承担。

避免笼统方向词，例如"往反方向走""往坏的方向发展"。直接写清楚变化发生在哪个变量、机制或读者判断上。

避免把本该自然展开的动词或修饰语压成单字收尾，例如"年份近""机构真""格式齐"。改成"年份较近""机构真实""格式齐整"。

少用口语化比喻和战争隐喻描述分析判断。尤其避免"长出来""很硬""很锋利""击穿""拆解""闭眼编"等词。直接说明问题在哪里、假设为什么不成立、影响范围是什么。

不要用"结构性"替代具体机制。写清楚是哪一层约束、冲突、激励或信息问题导致了结果。

不要用元评论代替论证。少写"本文旨在""这个框架说明""回到 X 场景"。直接提出研究问题、理论判断或证据含义。

中文段落需要自然承接。段首可以用"这里""这样一来""不过""反过来看""关键是"等轻承接词，但不要把文章写成条目堆叠。

链接文字要承载信息。不要用"这里""前作""之前讨论过的"做链接文本；应写文章名、功能名或具体名词短语。

## 常见替换

| 避免 | 改法 |
|---|---|
| 值得注意的是 | 直接写值得注意的内容 |
| 不难发现 | 直接呈现发现 |
| 本文旨在 | 直接写研究问题 |
| 本研究的意义在于 | 直接写贡献改变了什么 |
| 填补空白 | 说明填补哪一层理论空白 |
| 具有重要启示 | 说明对谁、在什么情境下有什么启示 |
